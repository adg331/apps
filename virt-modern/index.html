为什么是现在 · 01

虚拟化平台成了变量，数据底座必须是常量

续约改为按核订阅后，问题从「基础设施够不够」变成「已有的基础设施用得有多充分」。与此同时，平台选择正在变成按工作负载决定，而不是全公司一刀切。

示意图：平台名称仅为举例，不代表推荐顺序。

三种压力同时出现

预算：续约价格和商务条款不确定，按核计费让每一个核、每一 GB 内存都直接进成本。
风险：仓促迁移可能只是把问题搬了个地方，而不是解决问题。
机会：借这次重新评估，按工作负载制定平台策略。

四个动作，不必同时发生

评估：不急于下结论，先把替代方案评估清楚。
优化：在 VMware / VCF 上先拿到更多价值。
现代化：把选定的应用迁向容器、AI 与云原生模式。
运维：无论平台怎么变，可见性、保护和治理保持一致。
为什么是现在 · 02

从工作负载出发，而不是从平台出发

答案通常是组合：保留（KEEP）、迁移（SHIFT）、现代化（MODERNIZE），下线（RETIRE）永远是第四个选项。选一个示例负载，看它在三个维度上的位置落到哪条路径。

五个维度，让决策回到事实

数据可移动性：保护、迁移、治理。三条路径都需要它。

保留 · 01

在 vCenter 里完成存储运维，按负载选协议

ONTAP tools for VMware vSphere 把数据存储的生命周期、主机配置、自动化和保护集成进 vCenter，虚拟化管理员不用切换工具。同一套 ONTAP 同时提供块、文件和对象，不同负载选不同的数据存储形态。

ONTAP tools 在 vCenter 里做什么

数据存储生命周期：VMFS 与 NFS 数据存储的创建、扩容、回收。
主机配置：按存储最佳实践设置主机参数。
自动化：REST API 编排可重复的流程。
保护集成：vSphere 操作直接衔接存储快照与复制。

对制造业 IT 的意义

产线系统扩容不排队：MES、SCADA 历史库所在的数据存储在 vCenter 里直接扩，不必另开存储工单。
标准化落地到每个分厂：主机设置按同一套最佳实践下发，分厂少人值守也能保持一致。
保留 · 02

每卸载一项数据服务，就少买一份核数

按核计费之后，主机上用来处理存储的 CPU 和内存同样要付许可费。把复制、置零、克隆、去重压缩交给 ONTAP，主机核数就能留给业务 VM。

—存储处理占用的核数（软件定义存储）
—改用外部 ONTAP 后可腾出的核数
—相当于少买的主机台数

按区间估算（软件定义存储占 10–20% CPU；外部存储使存储相关 CPU 消耗降低 80–90%，此处取 85%）；示意计算，不含去重额外开销与网络、机柜等连带成本。

交给 ONTAP 的四类工作

数据路径卸载：VAAI 与 VAAI-NAS 把复制、置零、克隆、锁交给阵列。
快照与克隆：阵列快照和 FlexClone 秒级生成省空间的 VM 副本。
存储效率：内联去重、压缩、紧缩在阵列上完成。
高效协议：NFS 与 NVMe/TCP 每次 I/O 的主机 CPU 开销低。

新功能：NFS 数据存储支持 VAAI UNMAP

NFS 数据存储上删除的块可以回收给阵列，降低每 TB 成本。
核心观点：卸载不只是性能手段，它省下的是不必购买许可的核数与内存。
保留 · 03

把「感觉资源配多了」变成有数据的回收计划

Data Infrastructure Insights（DII）根据使用规律给出调整建议，并兼顾 vSAN、NUMA 和集群最小规模等约束。持续做，而不是一次性清理。

CPU 利用率内存利用率可腾空的主机

示意：12 台主机的利用率为假设值；调整后的目标水位取约 55% CPU、约 80% 内存。

DII 找什么

规格过大的 VM：CPU、内存长期分配远高于实际使用。
隐藏容量：已关机的 VM、孤立的 VMDK。
主机密度：按应用、部门标出利用不足的主机，对照许可成本。
映射到存储：VM 对应到 ONTAP 卷与 LUN，问题能追到底层。
7,536一次 90 天分析中识别出的可回收核数（客户案例）
33%基础设施利用率提升（IDC 对 DII 的调研）

对制造业 IT 的意义

换线、新项目上线时临时扩出来的测试 VM，往往没人回收。季度一次的 DII 复盘能把这些资源找回来。
保留 · 04

VCF 9.1 参考架构：计算与存储分离、跨站点双活

外部 ONTAP 与 VMware 最新方向一致，可以替代 vSAN。下图是 vSphere Metro Storage Cluster（vMSC）示例：两站点用 SnapMirror active sync 双活，第三站点异步复制，在线数据存储由 ARP/AI 防护。

设计要点

计算存储分离：容量和性能各自扩展，不用为了加存储买节点。
协议按层级选：NFS 求规模与简单，NVMe/TCP、NVMe/FC 给一级延迟敏感负载。
全闪存与对称双活 SAN：AFF、ASA 让高密度部署可预期。
深度集成：VASA/VAAI、ONTAP tools、VM 到 LUN/卷的可见性。

对制造业的价值

MES / SCADA 不断线：单个机房故障时，另一站点的主机直接接管，产线报警与数据采集不中断。
ERP 月结长事务：双活镜像零数据丢失，月结期间不必为站点风险停批。

迁移 · 02

NetApp Shift Toolkit：转换磁盘，而不是复制数据

源 VM 放在 ONTAP 的 NFS 数据存储上时，Shift 用 FlexClone 在原地生成目标格式的磁盘，不搬数据，所以转换耗时基本不随 VM 大小增长。

VM 大小：

转换耗时为厂商对比数据（分钟），非性能承诺；动画按比例缩放时间。

支持的转换方向

VMware ⇔ Hyper-V：VHDX，支持端到端迁移。
VMware ⇒ KVM：QCOW2 / RAW，可用于 OpenShift、Proxmox。
原生 KubeVirt：Shift 转换磁盘，Trident 导入为 PVC。
OLVM 与 OpenShift：提供 API 与示例脚本。

使用前提与收益

前提：待转换的 VM 必须位于 NetApp NAS（NFS）存储上。
收益：停机时间短、不绑定单一平台、减少迁移与许可开支。
对制造业：一个换班窗口内就能完成一批产线配套 VM 的切换。

现代化 · 01

KubeVirt：把虚拟机当作 Kubernetes 里的 Pod 来运行

每台 VM 是一个 virt-launcher Pod 里的 QEMU/KVM 进程，存储用 PVC，网络用 Service，健康检查用探针。OpenShift Virtualization 的底层就是 KubeVirt。点击组件查看说明。

为什么选择 KubeVirt

成本与锁定：开源，属于 CNCF 项目。
一个平台、一套技能：VM 与容器共用 kubectl、GitOps、RBAC。
渐进式现代化：老 VM 原样运行，新负载按云原生方式建设。
可移植：任何符合规范的 Kubernetes 集群都能运行同样的 VM。

实时迁移的前提

VM 磁盘的 PVC 必须是 ReadWriteMany（RWX）。
ONTAP 的 NFS、iSCSI、NVMe/TCP、FC 都能提供 RWX（块设备为 Block 模式）。
建议为迁移流量单独划一个网络。
现代化 · 02

NetApp Trident：一个 CSI 驱动接所有 ONTAP

Trident 连接 Kubernetes 与 NetApp 存储，开源免费，提供 7×24 企业级支持，是 OpenShift 认证 Operator。从管理员配置到容器挂载，一次存储供给分十步。

第 0 步

能力范围

协议：NFS、iSCSI、SMB、NVMe/TCP、FC。
访问模式：RWO、RWOP、RWX、ROX。
平台：FAS、AFF、ASA、AFX，以及各公有云上的 ONTAP 服务。
CSI 特性：快照、卷组快照、在线扩容、拓扑感知。

管理与安全

配额、QoS、PVC 自动扩容、原地快照恢复、SnapMirror 复制。
NVE / NAE 静态加密、主机侧 LUKS 加密、iSCSI CHAP、NFS 导出策略。
节点异常关机时自动卷故障转移；Prometheus 与 DII 监控。
现代化 · 03

存储设计决定 VM 性能：每块盘都是一个独立的 PVC

KubeVirt 的存储结构接近 vVol：每块虚拟盘对应一个 PVC。VMware 上是少数几个大数据存储，这里可能是成千上万个 PVC。选择盘的角色和负载类型，查看推荐的设置组合。

两层设置，别混在一起

Trident 与 PVC 决定「存储是什么」：后端协议（驱动）、volumeMode、accessMode。
KubeVirt 决定「怎么交给 VM」：以 disk 还是 lun 挂载、总线是 virtio 还是 scsi。
virtio：I/O 栈薄，每块盘一个 PCI 设备，速度优先。
scsi：完整 SCSI 命令模型，lun 透传必需，热插拔更好，规模优先。

落地建议

为 VM 负载单独建一个 SVM，并对各 SVM 设置 QoS，避免个别负载挤占资源。
NFS 负载用专用导出策略并关闭 showmount；CDI 导入优先用 NFSv4.x。

现代化 · 05

保护 KubeVirt 虚拟机：费力的做法与省力的做法

KubeVirt 自带快照与恢复，但需要按任务分别创建资源，也没有异地备份和容灾。Trident Protect 用一个 Application 资源覆盖 VM、PVC 与配置，备份、克隆、容灾一体完成。

三种工具，各管一段

Trident Protect：Kubernetes 原生资源，快照、备份（restic/kopia）、恢复，以及基于 SnapMirror 的异步容灾 AppMirror。
NetApp Backup and Recovery：基于 SnapMirror 的备份，策略化保护 VM 与容器，备份不可变、传输与静态均加密。
NetApp Disaster Recovery：编排存储、网络、计算的自动容灾计划，覆盖 OpenShift 与 VMware。

客户案例：一家游戏公司

迁到 OpenShift Virtualization 后，用 Backup and Recovery 按策略保护 Windows / Linux VM，备份送到 ONTAP S3 作为异地副本，团队不必成为 OpenShift 专家也能满足备份 SLA。
