性能 · 01

单卷、单文件性能最高翻倍

许多负载集中在一个卷、甚至一个文件上，此前很难用满单个控制器的资源。9.20.1 减少多客户端瓶颈，缓解卷"热点"。适用于 AFX 与 AFF A90 / A1K，NFSv3 与 NFSv4.x 均适用。

NFSv3 单卷性能，相对 9.18.1

依据 BKO3018 第 19 页；单文件读 op/s 为 2,000 个客户端的测试。NetApp 公布值，非性能承诺。

200%单卷顺序读 · 单文件顺序读
4×单文件读延迟降低

改进了什么

多客户端瓶颈减少：大量客户端同时访问一个卷时排队更少。
单控制器资源用得更满：单文件、单卷负载可以调动更多 CPU 与并发。
缓解卷热点：不必为了性能把数据拆到多个卷。

典型负载

EDA 临时空间：大量仿真作业集中写同一个 scratch 卷。
媒体制作：单个大文件的顺序读。
金融：集中在单卷上的分析与研究负载。

简化与运维 · 01

增强的均衡放置：问题出现之前就把卷挪开

创建时按性能或容量优先选位置；运行中检测持续的空间或性能倾斜，再给出移动建议或自动移动。先注入一个热点，再切换两种模式看区别。

状态

再平衡的三步

1 · 设置放置优先级：配置时选择性能优先或容量优先，初始放置即做出最佳选择。
2 · 检测持续热点：识别持续的空间或性能倾斜，而不是瞬时尖峰。
3 · 建议或移动：建议模式只提示；自动模式由 ONTAP 自行移动卷。

简化与运维 · 04

部署、迁移与对象存储的更多简化

把容易出错的手工步骤交给 ONTAP：压缩算法转换、镜像安装与加节点、FlexGroup 创建参数、S3 存储桶的默认策略。

MIGRATION · QAT
迁移到 QAT 平台的自动转换
支持 QAT 的平台使用更新的压缩算法；迁移后旧数据可能仍沿用旧算法，影响性能与节省。ONTAP 自动完成转换。
AUTOMATION · REST
镜像安装与加节点自动化
通过 REST 完成镜像安装与节点添加，可脚本化、可重复，能与 Ansible 配合，减少易错又耗时的手工操作。
FLEXGROUP · SLO
按 SLO 创建 FlexGroup
指定性能优先或容量优先，SLO 策略自动决定成员卷数量和 QoS 策略组，不用再反复斟酌部署参数。
FLEXGROUP · SNAPSHOT
FlexGroup 快照空间回收
在 FlexGroup 层面查看快照占用的空间，需要释放容量时能判断该删哪些快照。
S3 · INTEGRITY
NAS-S3 存储桶校验和
多协议（NAS-S3）存储桶支持校验和验证，增强数据完整性。
S3 · CAPACITY
过期对象清理与默认桶大小
更快清理过期对象，容量回收更可预期；可定义存储桶大小的默认策略，创建时少做决定。

安全 · 02

NFS over TLS 延伸到云：一套加密策略覆盖混合云

9.19.1 在本地 ONTAP 上提供了 NFS over TLS（RFC 9289）。9.20.1 把同样基于 TLS 1.3 的传输加密带到各大公有云中的 NetApp 存储服务。

依据 BKO3018 第 36 页。各云服务的具体可用时间与区域以其各自的发布说明为准。

带来的变化

统一策略：在本地、AWS、Azure、Google Cloud 上应用一致的 NFS 安全策略与控制。
简化运维：减少对 Kerberos、IPsec 和各云自有安全机制的依赖。
合规与零信任：用标准的 TLS 1.3 保护传输中的 NFS 数据。

性能代价对比（9.19.1 测试）

AFF A800 双节点、64 个卷、NFSv4.1、8K 随机 50/50 读写。依据 BKO3018 第 33 页。

勒索防护可调，管理面与链路都更硬

ARP/AI 的快照与响应现在可以按三种模式设置。切换模式看检测前后的快照行为，右侧是同版本的其他安全增强。

增强项说明
MAV 对接 Entra 组多管理员审批从 System Manager 路由到 Entra / AD，用现有组代替另建一套 ONTAP 账户。
FPolicy 支持 NFSv4.2 与 S3利用 NFSv4.2 扩展属性与安全标签，并能监控对象操作，用于审计、合规与网络韧性。
REST API 防 DoS保护管理平面，抵御连接洪泛。
加密密钥韧性可通过加密文件或 USB 找回口令，启动时读取缓存密钥；S3 密钥轮换借助冗余密钥减少停机。
FC 链路加密FC-SP3（FC-SP-2 ENC）标准加密，卸载到 HBA，性能影响很小。
持续可用 · 01

复制走 FC，FlexGroup 也能零 RPO

纯 FC 的企业数据中心过去要为复制单独铺 IP 网络。9.20.1 起 SnapMirror 可以直接跑在现有 FC fabric 上；FlexGroup 也补齐了同步复制。切换查看两种复制网络。

示意图依据 BKO3018 第 42 页。适用于 AFF 统一存储、ASA 与 FAS。

SnapMirror over FC NEW

支持 SnapMirror 主动同步、SnapMirror 异步与 LockVault。
去掉了复制对 IP / 以太网的前提，纯 FC 站点也能做容灾复制。
直接复用现有 FC 基础设施承载容灾流量。

FlexGroup 能力补齐 NEW

零 RPO：FlexGroup 支持 SnapMirror 同步与主动同步。
防篡改快照：SnapMirror 同步支持防篡改快照，与 FlexVol 能力一致。
AFX · 01

磁盘框弹性：坏掉整个磁盘框，数据仍可访问

RAID-TEC 最多容忍 3 块盘同时故障。此前一个 RAID 组按整框排布，坏一个框就是坏 24 块盘；9.20.1 把每个 RAID 组分散到多个框，每框只放 3 块。

示意：8 个磁盘框 × 24 块盘，简化为不画校验盘与备盘。布局依据 BKO1003 第 21–24 页。

结果

使用约束

可选、默认关闭：只能在创建集群时启用。
每个 RAID 组在每个框上 3 块盘，RAID 组总大小随之变化；RAID 组最少 8 块盘。
最少 3 个框，建议 8 个以上；96 块盘的 RAID 组需要 32 个框。
每个 RAID 组 1 块备盘，另有全局备盘池。
AFX · 02

分布式 FlexClone：克隆不再挤在一个节点

ONTAP 的卷归属于节点，FlexClone 默认建在父卷所在节点。同一负载的大量克隆都压在一个节点上，就成了瓶颈。9.20.1 起 AFX 的克隆可以不拆分地移到其他节点。

示意图依据 BKO1003 第 25–26 页、BKO3018 第 29–30 页。

机制

克隆先在父卷所在节点创建，再无需拆分地移动到其他节点。
利用 AFX 解耦架构，所有节点都能访问共享容量池，移动不搬数据。
每个父卷最多 255 个克隆（沿用既有上限）。

适合的负载

EDA：批量回归为每个作业克隆工作区。
软件开发：大量构建与测试并行使用代码副本。
媒体制作：多个团队并行处理同一素材的副本。

同版本的 AFX 写性能目标

讲者口径：AFX 2K 在 9.20.1 上的单节点写吞吐目标为 17.2–17.3 GB/s（方向性目标，非承诺）。

总结 · 02

9.20.1 带来了什么

讲者在 BKO3018 中的结论很直接：尽早升级到最新的 ONTAP，才能拿到最新的功能与最好的性能。规划时可以按下面四个方向评估。

01 · 性能
热点卷不再是瓶颈
单卷 / 单文件性能最高 2 倍、读延迟降低 4 倍，删除与重命名不再拖累其他流量。
02 · 运维
把判断交给系统
均衡放置自动发现热点，SLO 决定 FlexGroup 参数，TDZ 自动配 FC 分区，效率报表反映真实节省。
03 · 安全
权限下放，边界更清楚
租户在 GUI 自助管理，身份直通 AD，加密覆盖混合云与 FC 链路，ARP 响应可按需设定。
04 · AFX
更耐故障，更能并行
单框故障数据仍可访问；克隆分布到多个节点，批量并行负载不再挤在一处。

升级评估清单

AFX 磁盘框弹性只能在创建集群时启用；现有集群需要评估是否值得重新部署。
均衡放置的自动移动模式会主动移动卷，先在建议模式下观察一段时间。
SnapMirror over FC、TDZ 依赖交换网络能力（FC-GS-7 TDZ 扩展），先确认现网交换机型号与固件。
云上 NFS over TLS 以各云服务的发布为准，规划前逐项确认。
