EVOLUTION · 版本演进

同名产品，不同的架构

AIDE 在 2025 年随 AFX 发布；2026 年 Insight 重新定义为与存储解耦的纯软件服务。本幕是唯一涉及旧版的页面，此后各幕只描述新版。

02
ARCHITECTURE · 架构全景

五层结构，全部运行在自有环境内

数据源 → 采集 → 目录 → 能力 → 接口；NetApp Console 作为托管控制面。点击组件查看说明，切换叠加路线图组件。

边界：扫描、目录与操作都在自有基础设施上；数据和元数据不离开本地环境。
控制面：部署、角色、界面经 NetApp Console；Console Agent 负责本地与 Console 的连接和认证。
解耦：采集只依赖标准协议，存储侧不装代理、不改架构。

DEPLOYMENT · 部署模型

单节点与多节点，按增长后的体量选型

Console 不负责置备基础设施：准备主机或集群后，从 Console 复制预生成的安装命令执行。两种部署相互独立，不支持互相迁移；部署后也不能靠加资源自动扩容，规格要按几年后的体量选。

规格为文档推荐基线（按 3～4 天完成首次全量扫描设计），不是硬上限；欠配会拉长首扫，明显超出所部署规格时扫描可能停滞，可在健康监控中排查。

      SCANNING · 扫描机制

      挂载、遍历、索引、循环

      Metadata Engine 通过 NFS / SMB 挂载共享、S3 列举对象，提取文件系统元数据写入目录；一轮扫描完成后立即开始下一轮，以重扫识别新增、修改与删除。

      扫描日志 · 示意
      # 点击"演示一轮扫描"

      日志为示意，非真实输出格式。

      扫描运维
      • Auto-scan：按系统打开，覆盖现有与将来新增的资源；关闭后可逐个资源开关
      • Pause / Resume：按系统暂停与恢复，避开生产高峰
      • Scan all / Retry all scans：数据大幅变化后全量重扫；先修复凭据 / 网络 / 权限问题再重排
      • Deactivate：停止扫描但保留配置
      • Health monitor：看 Pod、节点与 CPU / 内存 / 磁盘压力；内存与磁盘告警最容易打断扫描
      使用结论前：核对各系统最近扫描时间与覆盖完整性——暂停、进行中或有错误都意味着部分数据尚未评估。

      09
      KNOW · 从发现到执行

      定位 → 确认 → 执行 → 策略 GA

      每个工作流都遵循同一路径：仪表盘定位、调查确认、执行操作、保存为策略持续监控。点击步骤查看细节。

      Tag

      需要时间或跨团队确认时先打标签，不改变文件位置。

      Archive

      仍有价值但不该占主存储，移到 NFS / SMB 冷存储目标，可留 breadcrumb 文件。

      Copy

      原件不动，三种方式：复制到 NFS / SMB；生成只保留命中文件的 FlexClone 过滤副本，迁移前先瘦身；或交给 Copy and Sync 搬运。

      Clean up duplicates

      同一文件多份副本只留一份：按最后访问 / 修改 / 创建时间选保留哪份，其余打标签、归档或删除；执行时重新精确比对。

      Delete

      永久删除不可恢复，即使文件仍活跃也会删除，需输入确认短语。

      当前限制 · 策略动作有限
      可挂"仅监控 / 邮件通知 / 永久删除"；自动归档与自动打标签暂不支持。
      当前限制 · 标签不可删除或改名
      标签定义只能从对象上移除，命名规范需提前约定。
      风险控制 · 删除策略每轮自动执行
      挂载删除动作的策略会在每轮扫描后无确认删除命中文件，建议先以监控模式观察。

      12
      ACTIVATE · 激活 · MCP 访问

      让 Agent 读懂数据资产 GA

      AIDE 内置 MCP 网关（Governed Access Gateway）：管理员把扫描过的数据划成"集合"，用 Microsoft Entra ID 的 scope 决定谁能查哪个集合；AI 客户端只能在授权集合内查元数据、打标签，读不到文件内容。

      对话与工具调用 · 示意

      工具名取自 AIDE 1.3 文档；路径、属主与结果为示意数据。已验证的客户端：Claude Code、Claude Desktop、Cursor、OpenCode。

      MCP 工具作用
      get_collection返回本次连接限定的集合
      search按文件名前缀、文件类型、属主查元数据，分页返回路径、大小、修改时间、属主
      list_tags列出租户内的标签及各自文件数
      create_tag新建标签
      tag_document给单个文件加 / 去标签，标签不存在时自动创建
      怎么管
      • 授权粒度是集合，默认有"All files"集合
      • Entra ID 认证；网关只校验令牌，不签发、不保存密钥
      • MCP 连接默认关闭，由管理员开启
      不能做
      • 读取文件内容、增删改文件
      • 修改数据源或新建集合
      • 按大小、日期、目录直接筛选：需逐页翻，结果可能不全
      授权要点：搜索不按文件级权限过滤，集合内匹配的文件都会返回。集合怎么划分，就是 AI 能看到什么。

      PROOF · 实测 · 智能体权限审计

      一句话，让智能体做全企业权限审计

      审计要问三件事：哪些数据开放得太宽、归谁、怎么修。跨全企业做，过去是一个项目。演示中智能体通过 MCP 查询 AIDE 目录，覆盖 NetApp 与非 NetApp 存储，全程不打开任何文件。

      智能体会话 · 示意
      发现 · 示意属主修复建议优先级

      每条发现都对应一个能联系的人和一个修复动作；首 7 天计划提交审批后才会执行。

      不打开文件：凭据类文件只按文件名找出，目录暴露只看元数据里的权限。
      每条都有人名：暴露按系统和属主排序，直接知道该找谁。
      人批准才执行：智能体只出计划，收紧权限、移走文件都由人决定。

      1.3 文档列出的 MCP 工具只有元数据搜索与打标签：开放目录和可访问人数在 Directories 视图中筛选（第 11 幕），凭据类文件可用 search 的文件名前缀条件查找。

      ROADMAP · DATAPELAGO

      在数据所在处处理数据 ROADMAP

      NetApp 于 2026-07 收购 DataPelago。其 Nucleus 引擎以 CPU / GPU 异构加速，在数据所在处处理数据，免改代码加速 Spark、Trino 与 Python。NetApp 计划将其与 ONTAP、AFX、AIDE 集成，集成形态与时间未公布。

      收购前的独立形态：以 Spark 插件（JAR）部署，运行在分析引擎所在的计算节点上（本地或云上 CPU / GPU），数据留在原有存储，上层作业免改代码。

      GETTING STARTED · 上手路径

      登记

      选定范围
