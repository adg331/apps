命令行变成了仪表盘，仪表盘长出了 API，API 长出了自动化框架

工具没有错，是规模变了

UNIFIED MANAGER

HARVEST + GRAFANA

脚本 + WIKI

四个阶段

事件：系统上发生的事实，量大、原始
告警：规则判定值得让人知道；有状态，维护窗口内可抑制
通知：邮件、webhook、Slack 或 Teams，可设免打扰时段；同一告警可同时进 ServiceNow
动作：告警自带修复，扩容、迁移 LIF、重新同步 SnapMirror，一键执行

没有你的同意，什么都不执行

每个修复动作执行前都预览具体的 ONTAP 操作，也可以复制等效命令到 CLI 自己执行
每个动作写入防篡改审计记录，可保留、可导出到 SIEM
参考场景中，容量告警从发现到解决约 2 分钟，全程有审计

自治资产 · 01 概念 · BKO2001

存储类是一份契约：写清楚什么必须成立，不写怎么做

它带着自己的自治策略和影响范围上限，是智能体要负责的对象，也是你审计的单位。同一个修复在两个类里行为不同，切换看看。

它为什么是契约

说明什么必须保持成立，而不是达成它的步骤
逐个目标携带自己的自治策略
携带你编写的影响范围上限
智能体对它负责，你按它审计

自治继承自类，不来自智能体

智能体对"何时行动"没有自己的主张，类就是契约
没有类就没有自治：未分类资源标记为覆盖缺口，永远不会被悄悄处理
限制写在你的策略里，而不是藏在模型里，所以自治行为可以推理
自治资产 · 02 概念

一张组织架构图，而不是一群智能体

一个协调者、四个专职角色，路径可检查。点击角色查看它从你桌上拿走的工作。

结构上的约束

监督者是唯一的协调者，专职角色之间不互相协商
独立验证者：行动前按目标给计划打分，行动后再给结果打分
共享运维记忆：一张实时的资产全景，带锁，两个智能体不会同时动同一范围
刻意保持很小的协作面，参照 NetApp 自己工程组织的运作方式

为什么不是蜂群

一群智能体在演示里很惊艳，在变更评审会上却无法辩护
组织架构图可以检查、可以配人、可以审计、可以解释
自治资产 · 03 概念

权限在模型之外：每个动作先过一道确定性闸门

任何拟执行的动作在触达系统之前都会被拦截，由一道智能体无法"说服"的规则闸门裁决，出错时默认关闭。选一个拟执行动作，看闸门怎么判。

动作与裁决的对应为示意，用于说明机制；具体规则由客户在存储类与策略中编写。

六条护栏

二元法则：不可信输入、敏感访问、状态变更，三者同时出现时必须有人参与
你的影响范围：上限来自你编写的类，而不是智能体
即时凭据：按任务签发，为该动作生成，用完即失效
幂等键：重试永远不会把同一变更执行两次
一键回滚：每个动作都自带反向操作
全局总开关：一个控制立即停止整个资产上的所有自治
即使模型困惑或被攻破，也无法超出你的策略允许的范围
