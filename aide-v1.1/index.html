EVOLUTION · 版本演进

同名产品，不同的架构

AIDE 在 2025 年随 AFX 发布；2026 年 Insight 重新定义为与存储解耦的纯软件服务。本幕是唯一涉及旧版的页面，此后各幕只描述新版。

2025 版 vs 2026 版
维度2025 · AFX 内置形态2026 · 纯软件形态
变化 01
从设备到软件

部署在已有的虚拟化或 K8s 平台上，单 VM 约 45 分钟完成安装。

变化 02
从单平台到全资产

同一目录覆盖多厂商、多站点、本地与云上的文件和对象存储。

变化 03 · 代价
从专有接口到标准协议

换来异构覆盖；新鲜度取决于扫描周期，源端承担扫描读负载。

变化 04
从全栈到先打底座

首发聚焦元数据；内容理解、向量化与检索进入路线图。

旧版依据 AIDE 1.0.0 文档（2026-05）；新版依据 AIDE 1.1.0 文档（2026-09-30）与 2026-09-29 新闻稿。

02
ARCHITECTURE · 架构全景

五层结构，全部运行在自有环境内

数据源 → 采集 → 目录 → 能力 → 接口；NetApp Console 作为托管控制面。点击组件查看说明，切换叠加路线图组件。

边界：扫描、目录与操作都在自有基础设施上；数据和元数据不离开本地环境。
控制面：部署、角色、界面经 NetApp Console；Console Agent 负责本地与 Console 的连接和认证。
解耦：采集只依赖标准协议，存储侧不装代理、不改架构。

      INGEST · 数据接入

      只需要标准协议

      AIDE 在协议层读取元数据，不需要存储厂商 API，也不在存储上安装代理；只要对外提供 NFS、SMB/CIFS 或 S3，就能纳入同一目录。

      06
      SCANNING · 扫描机制

      挂载、遍历、索引、循环

      Metadata Engine 通过 NFS / SMB 挂载共享、S3 列举对象，提取文件系统元数据写入目录；一轮扫描完成后立即开始下一轮，以重扫识别新增、修改与删除。

      扫描日志 · 示意
      # 点击"演示一轮扫描"

      日志为示意，非真实输出格式。

      扫描运维
      • Activate scans：添加数据源后不会自动扫描，需逐系统激活
      • Pause / Resume：按系统暂停与恢复，避开生产高峰
      • Scan all：数据大幅变化后立即触发全量扫描
      • Retry all scans：先修复凭据 / 网络 / 权限问题再重排
      • Deactivate：停止扫描但保留配置
      使用结论前：核对各系统最近扫描时间与覆盖完整性——暂停、进行中或有错误都意味着部分数据尚未评估。

      09
      KNOW · 从发现到执行

      定位 → 确认 → 执行 → 策略 GA

      每个工作流都遵循同一路径：仪表盘定位、调查确认、执行操作、保存为策略持续监控。点击步骤查看细节。

      Tag

      需要时间或跨团队确认时先打标签，不改变文件位置。

      Archive

      仍有价值但不该占主存储，移到 NFS / SMB 冷存储目标，可留 breadcrumb 文件。

      Copy

      备份或迁移前在第二位置保留副本，原件不动。

      Delete

      永久删除不可恢复，即使文件仍活跃也会删除，需输入确认短语。

      当前限制 · 策略动作有限
      可挂"仅监控 / 邮件通知 / 永久删除"；自动归档与自动打标签暂不支持。
      当前限制 · 标签不可删除或改名
      标签定义只能从对象上移除，命名规范需提前约定。
      风险控制 · 删除策略每轮自动执行
      挂载删除动作的策略会在每轮扫描后无确认删除命中文件，建议先以监控模式观察。

      TRUST · 信任 · 访问治理

      开放目录看得清，角色分权管得住 GA

      Directories 视图按权限筛选全组织可访问的目录，查看每个用户 / 组的读写权限；AIDE 自身的操作权限通过 Console 的两个角色分配。

      目录 · 示意属主权限摘要最近访问

      流程：筛选 → 打开详情查看 View permissions → 确认是否有意为之 → 保存为策略，在每轮扫描后监控新增暴露。

      11
      ACTIVATE · 激活 · MCP 访问

      让 Agent 读懂数据资产 GA

      首发提供 MCP 访问，使 Agent 与 AI 应用能以受控方式查询元数据服务层：有什么、在哪里、谁拥有、是否活跃、是否过度暴露。它提供的是元数据上下文，不是文件内容检索。

      对话与工具调用 · 示意

      工具名称和参数不是官方接口定义；MCP 配置以 AIDE 文档为准。

      是什么
      • Agent 与元数据服务之间的受控交互接口
      • 为助手与 Agent 提供更干净、更及时的元数据上下文
      不是什么
      • 不读取文件内容、不做向量检索，不能单独完成 RAG
      • 不是 Agent 平台，不负责构建或编排 Agent
      后续叠加：预览 代理式服务（数据到上下文）；ROADMAP 语义搜索、知识图谱、决策上下文。
      12
      ROADMAP · DATAPELAGO

      在数据所在处处理数据 ROADMAP

      NetApp 于 2026-07 收购 DataPelago。其 Nucleus 引擎以 CPU / GPU 异构加速，在数据所在处处理数据，免改代码加速 Spark、Trino 与 Python。NetApp 计划将其与 ONTAP、AFX、AIDE 集成，集成形态与时间未公布。

      处理路径 · 概念示意

      示意图仅用于说明"在数据所在处处理"的概念，不代表集成后的部署位置、架构或性能。

      计划集成 · 形态与时间未公布
      ONTAP
      统一存储
      AFX
      分离式全闪
      AIDE
      元数据服务
      部署位置未公布：Nucleus 将运行在存储控制器、独立计算节点还是其他形态，NetApp 尚未披露集成路线图与支持平台。
      收购前的独立形态：以 Spark 插件（JAR）部署，运行在分析引擎所在的计算节点上（本地或云上 CPU / GPU），数据留在原有存储，上层作业免改代码。
      收购后的方向：把算力移到数据层，与存储层对齐，主要是 ONTAP 与 AFX；在 AIDE 架构中对应采集层的路线图组件"存储侧数据处理"。
      说明：厂商宣称的性能与成本数字为厂商表述，非承诺；集成范围以官方后续发布为准。

      独立形态与收购后方向依据 DataPelago 文档、AWS APN Blog（2026-09）、NAND Research 与 Techzine（2026-07）的公开报道整理。

      14
      GETTING STARTED · 上手路径

      从一次全厂数据盘点开始

      评估期内免费使用（新闻稿：前 6 个月），覆盖 NetApp 与非 NetApp 存储；评估期后按届时的打包与定价执行，后续高级能力可能单独打包。

      STEP 1
      登记

      在 netapp.com/forms/map-your-data 登记，获取准备指南（登记不提供提前访问）。

      STEP 2
      选定范围

      选定首批共享 / 桶与首个用例：容量回收、迁移规划、访问治理或 AI 语料圈定。

      STEP 3
      准备环境

      准备 VM 或 RKE2 集群、Console Agent、网络与扫描凭据。

      STEP 4
      部署并扫描

      GA（计划 2026-10-23）后在 Console 部署、接入数据源、激活扫描。
